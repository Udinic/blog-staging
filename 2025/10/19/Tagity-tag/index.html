Tagity tag

October 19th, 2025

<banner photo>

Intro:

I was looking for a project that would both get my kids involved in electronics and actually be useful for them. At the same time, I wanted to make TV content more accessible: it’s all too easy for kids (and adults) to fall into the endless loop of short, addictive YouTube videos instead of enjoying a thoughtful episode of a TV series.

To make things trickier, a lot of the content they like is spread across different streaming services, or tucked away on my Plex server which can be confusing for kids to navigate on their own.

The solution: build an NFC tag scanner that plays shows or movies when you tap a credit-card–sized “Movie Card.”

(+ demo video, the one with the scanner on the wall)

The scanner is connected to my Home Assistant smart home using ESPHome - a framework that greatly simplifies creating custom smart devices.

The scanner runs on ESPHome - a framework that makes creating custom smart devices surprisingly simple, and connects to my Home Assistant setup. With my kids’ help, we created over 50 cards covering all their favorite shows and movies, and the collection keeps growing. It was such a hit that I built a second scanner for another room. To make it blend in, I designed and 3D-printed a small enclosure that matches the décor while keeping the scanner kid-friendly and accessible.

Building the electronics

The circuit is straightforward: connect an NFC reader module (PN532) to a microcontroller (ESP8266 WeMos D1 mini).

There are two ways to hook up the PN532: I²C or SPI. I went with I²C because it’s simpler - requires just 2 two data wires. For a tag scanner, throughput is minimal, so SPI’s extra speed doesn’t add any benefit. What it does add is more wiring (The MOSI, MISO, SCK and CS pins, also visible on the diagram above), which makes things unnecessarily messy.

One critical step: set the PN532’s mode correctly. The board has tiny DIP switches (or sometimes solder pads) to toggle between I²C and SPI. Make sure these match your chosen mode—otherwise you’ll be staring at a non-responsive scanner and wondering why nothing works. Let’s just say I learned that lesson the hard way 😅.

Once the jumpers were set, I wired the SDA and SCL pins from the PN532, to the Wemos D1 mini. You can map I²C lines to almost any pins; I chose D8 (for SDA) and D7 (for SCL). These need to match what we’ll later declare in the ESPHome config:

i2c:

sda: D8

scl: D7

pn532_i2c:

id: nfc_reader

After confirming the wiring, I soldered everything together. A pair of helping hands was invaluable here - keeping the boards aligned so I could stack them neatly and compactly. That’s important, since they need to fit snugly inside the enclosure, as we’ll see later.

With the hardware stacked and soldered, it was ready for the fun part - bringing it to life through ESPHome and tying it into Home Assistant, where we’ll write an automation to make the scanner react to different cards.

ESPHome Config Basics

The scanner runs on ESPHome, which makes connecting hardware like the PN532 reader almost trivial. Instead of writing firmware, you just declare the pins and components in YAML, and ESPHome takes care of the rest.

——————–

esphome:

name: tagitytag_scanner

platform: ESP8266

board: d1_mini

i2c:

sda: D8

scl: D7

scan: true # optional, helps confirm wiring

pn532_i2c:

id: nfc_reader

——————–

“Installing” this config on our microcontroller involves connecting it to the computer and using 2 web tools that do everything. The first tool, ESPHome Builder, parses the yaml config and generates the firmware based on the info on that config. The second tool, ESPHome Web, connects to your device via USB cable and flashes the firmware onto it. There are plenty of good instructions for the process, such as this youtube video or the official ESPHome instructions.

From ESPHome → Home Assistant

Once the firmware is loaded onto the Wemos D1 mini, Home Assistant automatically detects the device and prompts you to add it as an integration.

(Insert screenshot of the device in HA’s integrations page)

From there, the scanner can report any NFC tags it detects. Home Assistant has an Event Listening feature under Developer Tools, a quick scan of any card, while listening to “tag_scanned” events, will show some useful data for the card and the tag scanner. tag_id is the card’s unique ID and device_id is the tag scanner’s unique ID.

We could write data onto the cards, but we won’t do that here. There’s no need to complicate the process of adding new cards, since each card already has a permanent unique identifier. We’ll design an automation that maps each card’s Tag ID to the content we need to play.

Writing the Automation

There are a few ways to set up the automation. I liked the structure Xavier at Simply Explained shared, it keeps the mapping of Tag IDs to content easy to read and update.

I made a few changes of my own:

  • Support for multiple scanners (so different rooms can have their own devices).

  • Some tweaks to handle different types of content (Plex, Netflix, etc.).

Here’s how it works.

First, the trigger is a tag_scanned event, the same one we saw earlier when testing the scanner with the Developer Tools. The automation will be triggered when such an event is fired.

We’ll define all the difference variables the automation uses:
SCANNER_MAPPING - A simple mapping between Scanner IDs to the TV entity they should operate on. We can get the Scanner ID using the Event Listener tool we saw earlier.
TARGET_TV - This variable resolves to the TV entity the automation targets, based on the Scanner ID that was provided by the tag_scanned event (i.e. trigger.event.data.device_id). In this case, it defaults to the Living Room TV if the scanner is not listed in the mapping.
CARD_MAPPING - Maps each card’s Tag ID to the content it should play.

Each card mapping includes the Tag ID, a name (just for readability) and the Content ID. The automation supports a few content types, for several streaming services and Plex. We’ll see below how we deep link to open the content.

Next, we’ll prepare the TV by turning it on, if it’s not already.

And now we’ll handle each content type by generating a different Deep Link URL, based on the service we need to start the playback on. In this example, we’re handling Netflix content by taking the card’s content ID using the CARD_MAPPING, and plugging that into Netflix’s Deep Link URL. This URL works on an Apple TV, which is what I have connected to my TVs, other streaming devices might require other ways to open a specific content on a specific streaming service.

Deep Linking to Content

For streaming services like Netflix or Disney+, we can use deep links to jump straight into the right show or movie on the Apple TV. Here’s a list of deep links I use for various streaming services and support in my automation:

Disney+: https://www.disneyplus.com/en-gb/play/<Content ID>

Netflix: https://www.netflix.com/watch/<Content ID>

Hulu: hulu://watch/<Content ID>

Plex Movie/TV Show: plex://play/?metadataKey=%2Flibrary%2Fmetadata%2F<Content ID>&server=<Plex server ID>

Plex Playlist: plex://play/?metadataKey=%2Fplaylists%2F<Content ID>&server=<Plex server ID>

Creating the Content Cards

The electronics and automations are only half the story — the real magic (and the part my kids loved most) was creating the Movie Cards themselves.

We used fanart.tv as our main source for high-quality TV and movie artwork. It has a huge collection of posters, logos, and backgrounds that work perfectly for this kind of project.

Once we picked the right art, we copied it into a Google Doc and resized it to the dimensions of a credit card (Tip: resize to Width 2.12 inch, Height: 3.36 inch, Ratio: 1.583333).

This keeps the aspect ratio consistent so the art doesn’t look stretched or squashed when printed.

(Insert photos of resizing in Google Docs)

After resizing, we printed the sheets and ran them through a laminating machine. The laminate not only makes the cards sturdy enough for repeated use, but also gives them that satisfying “real card” feel.

(Insert photos of Emma working on the cards)

Onboarding a New Card

Once the physical card is ready, the final step is onboarding it into Home Assistant. To make things easier, I’ve added to the automation a fallback in case we scan a card that’s not assigned to any content, which prints the card UID to Home Assistant’s Logbook.

This makes it super easy to grow the collection - every time we want to add a new Movie Card, we just pick art, laminate, scan once, and drop the Card’s UID into the automation with the content we want to play.

3D Printing the Enclosure

With the electronics and cards ready, the last step was giving the scanner a proper home. I wanted it to be both accessible for the kids and subtle enough to blend into the room’s décor.

Instead of designing something from scratch, I started with an existing enclosure I found online and modified it. To personalize it, I asked ChatGPT to create a simple logo for the project, then imported that into the 3D model’s lid. The result was a clean, kid-friendly enclosure with a custom logo that makes it feel like a finished product.

(Insert render/screenshot of the enclosure with logo)

I printed the design on my Bambu Lab printer, using standard PLA and 3 walls for sturdiness. The compact stack of the PN532 and Wemos D1 mini fit snugly inside, with just enough room for the wires and solder joints.

Bringing It All Together

With the hardware soldered, the enclosure printed, the Movie Cards laminated, and the automation wired into Home Assistant — it was time for the payoff.

The process feels natural:

  1. Pick a Movie Card.

  2. Tap it on the scanner.

  3. Within seconds, the show or movie starts playing on the TV.

No menus, no remotes, no digging through apps. Just the card, the scanner, and the content.

It’s been a huge success in our house — my kids love the ritual of picking a card and watching it come to life, and it gives them a healthier, more intentional way to choose what to watch.

Closing Thoughts

This project started as a way to combine electronics tinkering with something useful for the family, and it turned into one of our favorite weekend builds. Between the hands-on soldering, designing the cards, and the 3D-printed enclosure, everyone had a part to play — and the end result is something we use every day.

The best part? It’s endlessly extendable. Adding a new card is as simple as grabbing artwork, printing it, laminating it, and mapping the tag. The kids are already planning which shows to add next.

If you’d like to build your own, all the code snippets, 3D model, and automation examples are linked above. And if you do make one — I’d love to hear about it!
